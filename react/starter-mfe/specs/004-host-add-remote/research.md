# Research: Host add-remote

**Feature**: `004-host-add-remote` | **Date**: 2026-08-02

## R1 — Where to persist remotes[] updates

**Decision**: Append to `starter.role.json` `remotes[]` and regenerate `src/app/remotes/loaders.generated.ts` via existing `generateLoadersSource`; set `.env` key from `urlEnv`.

**Rationale**: Init/webpack already treat `starter.role.json` + generated loaders + env URLs as the source of truth (`remotesFromMeta`, `DefinePlugin` remotes map). Matching that path avoids a second registration channel.

**Alternatives considered**: Hand-only webpack edits (error-prone); separate remotes registry file (duplicates metadata); runtime-only window map without rebuild (insufficient for MF `remotes` compile-time map).

## R2 — Port vs URL input

**Decision**: Accept `--url=<absolute http(s) remoteEntry URL>` **or** `--port=<1-65535>`; port expands to `http://${DEV_HOST|127.0.0.1}:${port}/remoteEntry.js`. Require exactly one of url/port.

**Rationale**: Spec clarification; aligns with compose harness URL shape and `isValidRemoteUrl`.

**Alternatives considered**: Port-only (too rigid for remote hosts); host+port always (more flags than needed for local starter).

## R3 — Where to store per-remote props

**Decision**: Add optional `remoteProps` map on `starter.role.json`: `{ [alias: string]: Record<string, unknown> }` with JSON-serializable values only. Bake as `__STARTER_REMOTE_PROPS__` in webpack for host builds. Hand-edit this map for later changes (no update CLI in v1).

**Rationale**: Single documented file for registration + props (FR-016); mirrors remotes bake pattern; unknown aliases ignored at read time (FR-017).

**Alternatives considered**: Separate `starter.remote-props.json` (extra file to discover); TS module only (worse for CLI writes); props nested inside each `remotes[]` item (harder to leave props for removed aliases / ignore stale keys cleanly—still possible, but top-level map matches “ignore unknown alias” cleanly).

## R4 — How LoadRemote applies props

**Decision**: `LoadRemote` resolves `getRemoteProps(alias)` (empty object if missing/unknown), strips any caller `embedded` key from the bag, then renders `<LazyRemote {...props} embedded={true} />`.

**Rationale**: FR-012/composition defaults authoritative; prevents custom props from disabling embedded mode.

**Alternatives considered**: Deep merge with defaults object (unnecessary); React context-only without props on expose (breaks MF component contract simplicity).

## R5 — Sample observability prop

**Decision**: Standard sample prop key `title` (string). `FederatedRemoteApp` accepts `title?` and surfaces it on Route 1 (e.g. heading subtitle or `data-testid="demo-remote-host-title"`). Own-app with no prop: current copy unchanged.

**Rationale**: FR-018 / SC-006; minimal contract surface; dual-mode safe.

**Alternatives considered**: Generic `hostProps` dump in UI (noisy); require every remote implement a shared package interface (out of scope for starter).

## R6 — CLI identity defaults

**Decision**: Required `--alias`. Optional `--name` (default alias), `--expose` (default PascalCase of name → `./Name`), `--federation-name` (default from name). Optional `--props='<json object>'` on add. Reject duplicate alias. Host role only.

**Rationale**: Matches `normalizeRemoteEntry` / init `--remote` conventions; FR-007/009/015.

**Alternatives considered**: Reuse exact `--remote=alias:name:...` string only (less clear for url/port/props); interactive prompts (nice-to-have, not required for v1 CI).

## R7 — Loader generation ownership

**Decision**: `add-remote` calls the same `generateLoadersSource(remotes)` as init; update file header comment to “Generated by init / add-remote”.

**Rationale**: Single generator avoids drift.

**Alternatives considered**: Incremental patch of loaders file (fragile).

## R8 — Standalone / remote non-regression

**Decision**: No changes to `standaloneRoutes`, `hostRoutes` tree shape, or `App.tsx` useRoutes path. Remote expose remains `FederatedRemoteApp`. Webpack `__STARTER_REMOTE_PROPS__` only meaningful for host; remote/standalone builds get `{}`.

**Rationale**: Spec User Story 5 / FR-008.

**Alternatives considered**: None viable without violating constraints.
